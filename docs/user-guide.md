# 使用指南

## 1. 准备地点表

每行一个地点，建议使用稳定编号。以下为演示格式，不是正式研究坐标：

```csv
ID,名称,lon,lat,coordinate_system
DEMO001,演示点,114.30,30.50,GCJ-02
```

可使用 CSV 或 `.xlsx`；支持常见中英文表头，导入后仍需检查字段映射。CSV 优先保存为 UTF-8，程序也尝试识别 GB18030 等编码。

- 经度在前、纬度在后，不能选择同一列。
- 明确原始坐标系，不凭数值外观猜测 WGS84 或 GCJ-02。
- 正式研究优先核对实际可导航入口，不将行政中心自动视为入口。
- 自带 `resources/test_points.csv` 含测试异常，适合体验校验功能，不应直接作为论文样本。

## 2. 先用模拟模式

导入少量客源地，在“目标地点”维护少量目的地，创建即时任务，检查任务状态和导出文件。模拟数据只说明操作流程可运行，不说明真实交通状况。

## 3. 真实查询

在“系统设置”选择高德并配置 Web 服务 Key。默认优先保存在系统凭据库；凭据库不可用时，只有明确选择后才会保存本机明文文件。

先完成少量真实路线查询，核对地点、方向、预计时间和返回状态，再安排全量采集。频率、额度与服务权限以个人账户实际配置为准。

## 4. 安排采集

确认起终点数量、查询方向、日期、时段和采集窗口。立即执行用于当前采集；定时执行用于未来发起查询，不会请求指定时刻的历史或预测路况。

电脑需要持续开机、联网、不休眠。批量请求会依次或并发完成，应使用实际请求时间判断是否满足研究窗口要求。

## 5. 核查及导出

检查成功、失败、待采和错过窗口等状态，区分模拟、试采和正式数据。导出明细、汇总或研究数据包后，保留请求记录与字段说明。

比较多个日期时，核对策略、方向、实际查询时间和共同有效路线。失败与缺测不能填成“不可达”，也不能用模拟值补齐正式观测。

## 常见问题

### 浏览器未打开，或需要重新进入

保持原应用运行，再次启动程序会尝试打开同一数据目录的已有实例。启动器使用本机会话令牌，不要只输入一个猜测的端口地址。默认端口冲突时程序会选择其他可用端口。

### 关闭网页后还在运行吗？

关闭标签页不会关闭本地服务。正常结束请使用页面左侧“退出应用”。不要在定时采集过程中退出应用。

### 高德查询失败怎么办？

核对 Key 类型、权限、账户额度和网络；查看返回错误码和任务状态，确认问题后再重试。提交问题时不要包含 Key 或完整鉴权链接。

### 数据在哪里？

界面系统设置会显示本地数据目录。默认由 `platformdirs` 选择系统用户数据路径；也可用 `--data-dir` 或 `TRAFFIC_DATA_DIR` 指定。备份前先正常退出应用，并备份完整数据目录，不要只在运行时复制数据库文件。

### 如何分享问题？

提供系统、Python版本或打包版来源、复现步骤、脱敏后的最小输入和错误提示。不要分享 `credentials.json`、`instance.json`、真实 Key 或完整私人研究数据库。
