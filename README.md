## 这是什么

本系统帮助研究者管理地点坐标，并批量获取起点到目的地的驾车路线、道路距离、预计行车时间和实际查询时间。适合需要对多个地点、多个日期或多个时段进行重复采集的本地研究。

它是一个**研究数据采集与整理工具**，不是导航软件，也不生成历史路况或未来预测路况。

## 适合谁

| 使用者 | 可以用它做什么 |
| --- | --- |
| 旅游管理、旅游地理与交通地理方向的学生和研究者 | 比较客源地到景点、乡村旅游重点村等目的地的驾车可达性 |
| GIS 与空间分析人员 | 导入坐标表，批量查询道路距离和预计行车时间，并整理为分析数据 |
| 规划与区域研究人员 | 按日期和时段采集路线结果，检查采集是否完整 |

如果只需要少量路线查询、实时导航、交通预测或历史交通回放，本系统并不适合这些用途。

## 功能一览

| 地点与坐标 | 计划与路线 |
| --- | --- |
| 🗂️ **地点资料**<br>导入 CSV/Excel，识别常见中英文表头；检查坐标、编号和无效记录。 | 🕒 **计划采集**<br>立即查询或安排多日计划；保存每条路线的实际请求和响应时间。 |
| 📍 **坐标与路线**<br>记录或转换 WGS84、GCJ-02、BD-09 坐标；支持完整路线比较和附近目标模式。 | 🔁 **去程和返程**<br>分别查询客源地到目的地的去程，以及目的地返回客源地的路线。 |
| ✅ **采集核查**<br>查看成功、失败、待采和错过时间的记录；缺测不会被当作“不可达”。 | 📦 **数据导出**<br>导出路线明细、汇总、请求记录及字段说明，供后续分析使用。 |

### 地图服务

- **高德路线服务**：配置高德 Web 服务 Key 后，向高德发起驾车路线查询。实际可用性取决于 Key 权限、账户额度、网络和接口返回。
- **模拟模式**：用于熟悉流程和测试软件操作，不会调用真实路线服务，生成的数据不能作为研究观测。

## 一次研究通常这样进行

```mermaid
flowchart LR
    A[准备起点与目的地坐标] --> B[导入并检查资料]
    B --> C[配置地图服务与路线方向]
    C --> D[小规模试采]
    D --> E[安排日期和开始时间]
    E --> F[检查数量与采集窗口]
    F --> G[执行采集]
    G --> H[核对质量并导出]
```

1. **准备地点表**：每个地点至少有名称、经度、纬度和坐标系；批量研究建议同时提供稳定编号。
2. **导入并检查**：在“新建分析任务”导入客源地表并检查字段和坐标；在“目标地点”维护目的地，在“数据管理”查看已导入文件。
3. **选择地图服务**：熟悉操作时可先选模拟模式；真实采集前，在系统设置中配置高德 Key，并确认对应服务权限和额度。
4. **设置采集任务**：选择全部路线或附近目标，勾选去程、返程或双向，并安排查询日期和开始时间。
5. **先做小规模试采**：确认地点、路线策略、请求速度和采集窗口符合需要后，再安排完整任务。
6. **查看结果并导出**：检查成功、失败、待采和错过时间的记录，下载路线明细或完整研究数据包。

## 如何理解查询结果

> **计划时间表示“什么时候开始发起查询”，不表示接口会返回那个时刻的历史或预测路况。**

- **直线距离**：起点与终点之间的地理距离，不沿道路。
- **驾车距离**：地图服务规划路线的道路长度。
- **预计行车时间**：地图服务在实际请求时返回的预计耗时，不是车辆实测时间。
- **实际查询时间**：每条路线各自发出请求和收到响应的时间；一轮批量查询并非所有路线在同一秒完成。
- **缺测与失败**：请求失败、没有路线或错过采集时间都不等于“地点不可达”。未返回的路况信息保持缺失，不会推算为畅通或拥堵。

因此，跨日期比较应同时查看计划时刻、实际请求时间、方向和共同有效路线；不要把不同时间的查询直接当成同一时点观测。

## 在本机运行

Windows 用户可以直接运行打包版，也可以从源码启动；macOS/Linux 用户按对应命令运行。**下载打包版不需要另装 Python；从源码启动或自行打包需要 Python 3.11 或更新版本。**

### Windows：下载并运行

1. 打开[项目的 Actions 页面](https://github.com/gshota666/traffic-accessibility-system/actions/workflows/test-build.yml)。
2. 选择最新一条已完成且显示成功的 **Native platform test and build** 运行记录；如果最新记录仍在运行，等它结束后再下载。
3. 在页面底部的 **Artifacts** 区域下载 `traffic-accessibility-windows-latest`，然后解压。
4. 打开解压目录中的 `dist` 文件夹，双击 `交通可达性分析系统.exe`。软件会启动本机服务并打开浏览器页面。
5. 需要真实路线数据时，在软件“系统设置”中配置高德 Key；不配置时可使用模拟模式熟悉操作。

这是无需安装向导的 Windows 便携版，不是传统安装程序。运行期间不要退出软件；完成后使用页面左侧的“退出应用”正常关闭。

### Windows：从源码启动或自行打包

在 Windows PowerShell 中进入项目目录。以下命令不需要修改 PowerShell 脚本执行策略：

```powershell
py -3.11 -m venv .venv
\.venv\Scripts\python.exe -m pip install -r requirements.txt
\.venv\Scripts\python.exe start.py
```

如需自行生成单文件程序，再安装 PyInstaller 并运行构建脚本：

```powershell
\.venv\Scripts\python.exe -m pip install pyinstaller
\.venv\Scripts\python.exe scripts\build.py
```

生成的文件位于 `dist\交通可达性分析系统.exe`。Windows 版应在 Windows 系统上构建。

### macOS / Linux：从源码启动

在项目目录打开终端：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python start.py
```

启动后，在浏览器打开软件显示的本机页面。配置高德 Key 后才会向高德发起真实查询；模拟模式不会调用高德。

定时采集期间，电脑需要保持开机、联网且不休眠，应用也必须保持运行。关闭浏览器标签页不等于关闭应用，但退出应用或电脑休眠会影响后续查询。

### macOS 应用打包

```bash
python scripts/build.py
```

### 自动化测试

```bash
python -m pip install pytest
python -m pytest -q
node --check frontend/app.js
node tests/test_frontend_research.cjs
```

## 使用边界

- 使用高德前，请在高德控制台确认 Key、服务权限、调用频率和剩余额度；软件的本机限流设置不代表高德账户授权。
- 实际结果受网络、账户状态和接口返回影响。模拟数据只用于检查操作流程，离线性能测试也不能代表高德服务的实际速度。
- 本系统不提供车辆 GPS 实测轨迹、静态路网模型、历史路况、指定时刻预测路况、实时地图或自动生成的因果结论。
